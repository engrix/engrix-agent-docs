# Antarmuka & Jangkauan\n\n## Pertanyaannya\n\n> *Bagaimana menjaga empat permukaan UI tetap identik — tanpa membayar empat kali biaya perawatan frontend?*\n\nJawaban yang salah adalah empat aplikasi. Jawaban yang benar adalah satu aplikasi yang dirender pada empat ukuran, dengan hanya pembungkus desktop yang benar-benar kode native.\n\n**Dalam satu kalimat:** satu build frontend, empat rendering; keempatnya menjangkau engine dengan cara sama, dan shell desktop menambahkan fitur tingkat jendela (always-on-top, hotkey global, tray, pengecualian capture) tanpa menyentuh aplikasinya.\n\n## Empat permukaan, satu engine\n\nEngine chat yang sama bisa dijangkau lewat empat mode UI, semuanya dirender dari satu build frontend:\n\n| Mode | Bentuk |\n|---|---|\n| **Full** | Workspace lengkap: chat, file explorer, kanvas artefak, diff review |\n| **Panel** | Panel copilot melayang 380px di atas workspace |\n| **Bubble** | Satu tombol brand dengan titik status hidup |\n| **Desktop** | Jendela Electron frameless (400×640), always-on-top *di atas aplikasi lain*, hotkey global, ikon tray, dikecualikan dari screen capture |\n\n```\nsatu build (frontend/dist)\n    │\n    ├─ full   workspace   ← browser, route default\n    ├─ panel  380px       ← route sama, flag ui-mode\n    ├─ bubble tombol      ← route sama, flag ui-mode\n    └─ jendela desktop    ← shell Electron memuat dist dengan ?ui=desktop\n                             (frameless · always-on-top · hotkey global · tray)\n```\n\nMode-nya tinggal di satu store (`store/uiModeStore.ts`), yang menulis atribut `data-ui-mode` di root dokumen — CSS membaca atribut itu, jadi berpindah permukaan menyembunyikan app shell tanpa meng-unmount React. State chat dan stream selamat melewati perpindahan; pindah dari full ke panel tidak pernah memutus sesi.\n\nShell desktop adalah layer tipis: ia memuat build frontend identik dengan flag `?ui=desktop` dan tidak pernah menduplikasi atau menumbuhkan engine-nya sendiri — ia mendeteksi engine yang sudah berjalan lewat health check lalu menyambung. Flag URL itu sengaja menang atas preferensi tersimpan dan tidak pernah ikut dipersistensi, jadi jendela desktop tidak bisa tanpa sengaja terbuka lagi sebagai jendela mode browser. Satu codebase, satu dist, empat permukaan.\n\n## Apa yang bisa dijangkau agent\n\nInventaris tool (detail di [sistem tool](tool-system.md)) memberi agent jangkauan nyata lintas lingkungan:\n\n- **Mesin lokal** — terminal sandbox, filesystem, kernel Python persisten, tool kode semantik LSP, debugger, test runner\n- **Browser** — dual-engine: fork Firefox anti-deteksi untuk otomasi/kerja multi-akun, dan Chrome asli owner lewat CDP saat task butuh sesi login owner yang sebenarnya (dengan pagar profil terlindungi)\n- **Perangkat** — kontrol penuh ADB Android (tap/swipe/type/install/scrcpy) dan kontrol desktop Windows native (lihat/klik/ketik di jendela mana pun, UI Automation, pencocokan template piksel)\n- **Remote** — administrasi VPS berbasis SSH: shell (termasuk PTY persisten), filesystem remote penuh, transfer file, systemd, port forwarding\n- **Komunikasi** — manajemen channel bot Telegram + akses akun pribadi, email Gmail API dan IMAP\n- **Riset keamanan** — pipeline recon→scan→exploit, OSINT, threat intel, reverse engineering biner\n- **Git/GitHub** — operasi repo lokal dan administrasi GitHub remote penuh\n\n## Permukaan untuk output agent sendiri\n\nUI bukan cuma jendela chat. Dua permukaan ada supaya agent bisa menyerahkan pekerjaan dalam bentuk yang benar-benar dibaca manusia:\n\n- **Panel artefak** — dokumen dan halaman HTML hidup yang dipublikasikan ke panel yang bisa dibuka owner, dikomentari dengan anchor paragraf, dan diberi versi. Agent menulis ke sana lewat tool, bukan dengan meminta owner menyalin file.\n- **File explorer dan diff review** — setiap edit yang diusulkan agent mendarat sebagai diff yang bisa direview dengan langkah approval, bukan tulisan senyap.\n\nKeduanya didukung engine (`publication/` untuk artefak, `app/approvals.py` untuk edit), dan itulah sebabnya keduanya bekerja identik di setiap permukaan.\n\n## Deployment\n\nPortable pack membundel source, virtual environment, dan build frontend di balik satu launcher `engrix.exe` — taruh foldernya di path mana pun di mesin itu dan klik dua kali. Engine-nya sendiri tetap proses lokal biasa (ia butuh akses hardware nyata: kamera, ADB, kontrol desktop), sementara layanan pendukung jalan di Docker Compose.\n
